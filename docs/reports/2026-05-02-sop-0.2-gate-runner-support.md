## 1. Summary

This PR teaches the gate runner (`src/core/gate/gate-runner.ts`) to validate
against an explicit `SopProfile` so the SOP 0.2.0 required-section gates
(steps 00–18) become enforceable. The default runtime profile is unchanged:
`loadSopProfile()` still returns 0.1.0, `ocn init` still writes 0.1.0
snapshots, and every CLI / MCP / advance code path that does not pass a
profile override continues to use 0.1.0. The new override path is reusable
by PR 4 (advance through BUILD / VERIFY) without further engine changes.

Highlights:

- `runGate({ profile })` accepts an optional explicit `SopProfile`. When
  omitted, the runtime default applies (0.1.0).
- `loadSopProfileByVersion("0.1.0" | "0.2.0")` is a new typed,
  deterministic helper for callers that need to validate against a specific
  profile version. The default `loadSopProfile()` is untouched and still
  pinned to 0.1.0.
- The required-section matcher pipeline is reused as-is
  (`computeArtifactGateStatus` → `parseHeadings` → `matchSection`); no
  parallel matcher was introduced.
- New tests: `tests/unit/sop-0.2-gate-runner.test.ts` (83 tests).

## 3. Implementation summary

### 3.1 Gate runner — profile-aware validation

`src/core/gate/gate-runner.ts`:

```
RunGateOptions.profile?: SopProfile
```

When provided, `runGate` derives `requiredSectionsForStep` and
`artifactPathForStep` from the override profile instead of the default
loader. Audit events, error codes, blocked-vs-pass outputs, exit-code
mapping, lock semantics, and message wording are all unchanged.
Bilingual headings (`English｜中文`) continue to be matched by the same
pipeline that 0.1.0 used.

### 3.2 Version-aware profile loading

`src/core/sop/loader.ts`:

- Added `loadSopProfileByVersion(version: "0.1.0" | "0.2.0"): SopProfile`.
- Both versions are built once and cached; subsequent calls return the
  same instance.
- The original `loadSopProfile()` continues to return 0.1.0, by design.
- The original `STATE_ORDER` re-export is preserved for backward
  compatibility (still bound to the 0.1.0 ordering — same as today).

### 3.3 Matcher reuse

No new matcher was introduced. SOP 0.2.0 templates use the same canonical
+ bilingual heading shape (`Canonical｜中文`) that the 0.1.0 matcher
already handled, and `parseHeadings` + `matchSection` resolve them
unchanged.

### 3.4 No file-existence-only gate for 05–18 under SOP 0.2.0

Under SOP 0.1.0, steps 05–09 had no required sections (artifact-existence
gate). Under SOP 0.2.0, every wired step has at least one required
section, and the gate runner now correctly blocks any step 05–18 whose
artifact body is empty / lacks required sections — proven by the
`05-18 do NOT pass on file existence alone` test groups.

## 4. Tests added

New file: `tests/unit/sop-0.2-gate-runner.test.ts` (83 tests, ~1.1s).

Test groups (all derived programmatically from
`src/sops/default-ai-coding-sop/0.2.0/data.ts`, no hand-coded duplication):

1. **Coverage shape** — derives 19 wired 0.2.0 steps; every step has a
   gate entry; every gate has at least one required section; every step's
   `artifactPathForStep` resolves via the 0.2.0 profile.
2. **Missing artifact blocks every step** — for each of the 19 steps,
   `runGate({ profile: SOP_020 })` returns `ERR_GATE_FAILED` with
   `status=blocked`, `artifactPath=<expected>`, and
   `blockingReasons=["artifact_missing"]`.
3. **Empty artifact fails every step** — for each of the 19 steps, an
   empty `docs/NN-...md` file fails with the full required-section list as
   `missingRequiredSectionIds`.
4. **Partial artifact** — `step_build_plan` with only the first required
   section heading present fails with the remaining sections returned as
   `missingRequiredSectionIds` and `blockingReasons=["missing_required_sections"]`.
5. **Full bundled template passes every step** — for each of the 19
   steps, writing the bundled SOP 0.2.0 template under the seeded path
   yields `ok=true, status=pass, missingRequiredSectionIds=[]`.
6. **Bilingual headings** — `step_build_plan` and (regression)
   `step_information_architecture` pass when every required heading uses
   the bilingual `English｜中文` form.
7. **05–09 file-existence-only is NOT allowed** — for each of the design
   slot steps (05–09), an artifact containing only the H1 heading is
   blocked under SOP 0.2.0 (regression vs 0.1.0 where these steps had no
   required sections).
8. **10–18 file-existence-only is NOT allowed** — same regression for
   each strong-gated build/verify step.
9. **All 19 generated templates pass** — runs the bundled 0.2.0 templates
   one after another and asserts zero failures. Mirrors the per-step
   "full template" group with a single zero-tolerance failure list.
10. **Runtime default unchanged** — `loadSopProfile()` returns 0.1.0
    (10 wired steps total), `loadSopProfileByVersion("0.2.0")` returns
    0.2.0 (19 wired steps total), and `runGate` without an explicit
    profile still uses the 0.1.0 PRD required sections (regression — proves
    the default profile did not flip).

Existing 0.1.0 gate tests stay green (all 7 in
`tests/unit/gate-runner.test.ts`, all 5 in `tests/cli/gate.test.ts`,
all 10 in `tests/cli/check.test.ts`, all 8 in
`tests/unit/core-check.test.ts`).
