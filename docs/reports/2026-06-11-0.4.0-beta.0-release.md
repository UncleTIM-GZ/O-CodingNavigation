# Release report — o-coding-navigation@0.4.0-beta.0

> Date: 2026-06-11 · Channel: npm `latest` + `beta` (alpha preserved at `0.1.0-alpha.2`) · Tag: `v0.4.0-beta.0`

## What ships

**SOP 0.4.0 — Readiness Backbone** becomes the runtime default (DEC-030):

1. **Readiness cross-cutting gate** (AM-004 / DEC-028) — 55 falsifiable checks from 54
   curated IT roles, run inside `check`/`gate`/`advance` after the section + logic
   gates. Open-world semantics: block-severity tier-required checks must be `PASS` or
   `WAIVED`; `FAIL` and `UNKNOWN` both block (`ERR_GATE_FAILED`, exit 1) with bilingual
   `fix_hint`s. Ledger at `.ocoding/readiness.json`; open items surface in `ocn brief`.
2. **`ocn readiness list` / `ocn readiness waive`** — verdict table + conditional
   waivers (waive-with-probe: grant-time probe, re-verified every gate, expires on
   state change; human-only, audited `readiness_waived`).
3. **`ocn sop upgrade [--target <version>] [--plan]`** (AM-005 / DEC-029) — forward-only
   re-pin for existing projects: rewrites profile-owned snapshots, preserves
   `config.yaml` + progress cursor + artifacts, audits `sop_upgraded`. The migration
   path for every pre-0.4.0 repo.
4. **Runtime cutover** (DEC-030) — fresh `ocn init` pins 0.4.0 and writes
   `readiness-rules.yaml`; `resolveProfileForProject` now honors every known pin, so
   0.1.0–0.3.0 projects keep their exact pinned behavior until upgraded.

## Migration

```bash
npm install -g o-coding-navigation@latest
ocn sop upgrade --plan   # dry-run
ocn sop upgrade          # move the pin to 0.4.0
```

No migration needed to stay on an old profile — pins are honored as-is.
