## What's in this release

**就绪门准时激活：州粒度 → 步粒度修正（AM-014 follow-up）。** dogfood 暴露的真 bug 修复。

- **问题**：原实现把 block 检查的生效点算到**州/阶段**粒度。但一个州有多步——`rdy_ciso`/`rdy_ba`
  依赖 PRD（产出于 `step_prd`），`dueState=state_spec`，于是项目还在 `step_scope`（SPEC 第一步、
  PRD 尚未轮到）时它们就**提前**要 PRD 内容，破坏了步级别的"不提前"，还诱导会话 AI 越界提前写
  下一步的 `docs/02-prd.md`。
- **修正**：改为**步粒度** `dueStep(rule)` = 各输入在全局步序里最晚的产出步；`currentStep < dueStep`
  才 DEFERRED。`step_scope` 处只剩 `rdy_cio_cto`（要 scope 停止条件、本步产物）生效，
  `rdy_ciso`/`rdy_ba` 正确延到 `step_prd`。repo-probe → 策略州的第一步。

引擎/CLI 特性，规则手册与 0.4.0/0.5.0 行为不变（无 `precise_activation` 即旧行为）。
