# Release report — o-coding-navigation@0.7.0-beta.5

> Date: 2026-06-30 · Tag: `v0.7.0-beta.5` · Channel: npm `latest` + `beta`（`alpha` 保留在 `0.1.0-alpha.2`）
> SOP profile: `default-ai-coding-sop@0.7.0`（不变）。
> 版本号：`0.7.0-beta.4 → 0.7.0-beta.5`。

## What's in this release

**`ocn advance -H` / `--human` + 更清晰的拒绝提示（AM-013 副作用缓解）。** 纯 CLI 体验修复，
不动治理逻辑。

- **背景**：默认接线（AM-013 `ocn init`）往 `.claude/settings.json` 注入 `env.OCN_ACTOR=ai_agent`，
  导致**真人在 AI 会话里用 `!` 跑 `ocn advance` 也被判成 ai_agent → 手动模式下被拒**（之前没接线的
  项目不会，故老用户"一直能 advance"突然不行）。
- **新增 `-H` / `--human`**：`ocn advance -H` 等价 `--actor user`，覆盖 env 中的 ai_agent，让人类在
  AI 会话里一条短命令就能推进。显式 `--actor` 仍优先。
- **拒绝提示改成可照抄**：`Advance … is not delegated … a human must run \`ocn advance --human\`
  (or \`ocn advance\` in a plain terminal; or \`ocn auto on --phase 1|2|all\`)`——此前只说"a human
  must run ocn advance"，没提 env 陷阱、还容易误填 `--actor human`（合法值是 `user`）。

actor 是审计治理签名、非安全边界（`src/core/automation/actor.ts`），故该便捷标志不削弱任何边界。

## Verification

- `prepublishOnly` 门通过：lint + typecheck + `test:coverage` + build。
- **1303** 测试全绿（新增 `tests/cli/advance.test.ts` 用例：`-H` 覆盖 `OCN_ACTOR=ai_agent`、
  cursor 推进、审计记 `user`；plain advance 被拒且 cursor 不动）。
- 实测：`OCN_ACTOR=ai_agent ocn advance` 被拒（提示指向 `--human`）；`ocn advance -H` 跨
  DISCOVERY→SPEC 成功。
