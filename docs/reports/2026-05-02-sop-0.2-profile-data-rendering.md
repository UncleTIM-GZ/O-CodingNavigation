## 1. Summary

This PR adds the SOP 0.2.0 profile under `src/sops/default-ai-coding-sop/0.2.0/`
as importable data plus a deterministic YAML renderer. It mirrors the 0.1.0
module shape exactly (`data.ts` + `render.ts` + `sop.ts` + `gates.ts` +
`artifacts.ts` + `config.ts`) so the runtime switch in PR 3 / PR 4 of the
SOP 0.2.0 6-PR sequence can adopt 0.2.0 by changing one import path in
`src/core/sop/loader.ts` without restructuring the profile package.

What this PR ships:

- Full SOP 0.2.0 state graph: 8 states, 19 wired steps across DISCOVERY → VERIFY,
  empty stub `steps: []` for SHIP and REFLECT (same shape `state_build` /
  `state_verify` had in 0.1.0).
- 19 artifact paths (`docs/00-project-brief.md` through
  `docs/18-final-build-verdict.md`).
- Required-section definitions for every wired step using the EXACT canonical
  wording listed in DEC-023, with bilingual aliases following the 0.1.0
  `English｜中文` + bare Chinese pattern.
- Deterministic renderers `renderSopYaml()`, `renderGatesYaml()`,
  `renderArtifactsYaml()`, plus `canonicalSopSnapshotSignals()` for a future
  `detect_sop_version` extension.
- Two new unit test files: `tests/unit/sop-0.2-profile.test.ts` (14 tests) and
  `tests/unit/sop-0.2-render.test.ts` (12 tests).

What this PR does NOT change:

- Default runtime profile — `loadSopProfile()` still returns 0.1.0.
- `ocn init`, `ocn check`, `ocn advance`, `ocn brief`, `ocn doc create`, `ocn
  status`, `ocn gate` behavior.
- MCP tool behavior.
- Gate runner behavior.
- Markdown templates (templates 11–18 land in a later PR).
- `package.json` / `package-lock.json` / `.github/workflows` / `README.md` /
  `docs/quickstart.md` / `docs/mcp-usage.md` / `docs/20-decision-log.md`.

## 7. Runtime non-change confirmation

Verified locally with a fresh init in `mktemp -d`:

```
node dist/cli/index.js init
cat .ocoding/state.json
grep -R "0.1.0" .ocoding   # finds 0.1.0 in state.json, config.yaml, sop.yaml, audit
grep -R "0.2.0" .ocoding   # NO MATCHES
```

Confirmed:

- `state.json` records `sopProfileId=default-ai-coding-sop`,
  `sopProfileVersion=0.1.0`.
- Initial state remains `state_discovery / step_project_brief`.
- `.ocoding/sop.yaml`, `.ocoding/gates.yaml`, `.ocoding/artifacts.yaml`,
  `.ocoding/config.yaml` are still rendered from the 0.1.0 profile data.
- `loadSopProfile()` still returns `version: "0.1.0"` (pinned by an explicit
  regression assertion in `tests/unit/sop-0.2-render.test.ts`).
- No CLI command changed: `ocn init`, `ocn status`, `ocn brief`, `ocn doc
  create`, `ocn check`, `ocn gate`, `ocn advance`, `ocn capture log` —
  unchanged.
- No MCP tool changed.
