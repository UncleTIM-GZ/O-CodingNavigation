> Generated: 2026-05-02

## 1. Summary

This PR cuts the OCN runtime default profile over to **SOP 0.2.0**. After this PR:

- `loadSopProfile()` returns the 0.2.0 profile by default.
- A fresh `ocn init` writes `state.json` with `sopProfileVersion: "0.2.0"` and renders `.ocoding/sop.yaml | gates.yaml | artifacts.yaml | config.yaml` from 0.2.0 (8 states, 19 wired steps, docs/00–18 paths).
- Every runtime path — `check`, `gate`, `status`, `brief`, `advance`, MCP tools — reads the 0.2.0 profile by default and enforces its required-section gates.
- A fresh project advances deterministically through all 19 wired steps (`step_project_brief` → `step_final_build_verdict`); after the terminal step `advance` returns `ERR_STATE_MACHINE` because SHIP/REFLECT remain stubs.
- No legacy compatibility / migration code is shipped, per the user's explicit decision that no old projects exist.
- `loadSopProfileByVersion("0.1.0")` remains importable for tests that want to pin the legacy shape, but nothing on the default runtime path goes through it.
- No npm publish, no `latest` movement, no version bump, no git tag, no GitHub Release. Not GA. Cursor / Cline integrations remain unverified.

## 3. Runtime cutover

### 3.1 `loadSopProfile()` default

`src/core/sop/loader.ts`:

- Added `DEFAULT_SOP_PROFILE_VERSION: SopProfileVersion = "0.2.0"`.
- `loadSopProfile()` now returns `getProfile(DEFAULT_SOP_PROFILE_VERSION)`.
- Re-exported `STATE_ORDER` switched from `STATE_ORDER_010` to `STATE_ORDER_020`.
- `loadSopProfileByVersion("0.1.0" | "0.2.0")` retained — used only by tests that explicitly target the legacy 0.1.0 enforcement contract or compare deterministic 0.1.0 renderer output. No default runtime path goes through 0.1.0.

### 3.2 Fresh `ocn init`

`src/core/init.ts`:

- `state.json.project.sopProfileId / sopProfileVersion` are now derived from the loaded profile (`profile.id`, `profile.version`) rather than literal `"0.1.0"`. Flipping the loader is therefore the single source of truth for the runtime version.
- All four snapshot files (`sop.yaml`, `gates.yaml`, `artifacts.yaml`, `config.yaml`) come from `loadSopProfile()` and now reflect the 0.2.0 rendering automatically (8 states, 19 wired steps, `docs/00`–`docs/18`, `version: 0.2.0` in `config.yaml`).

### 3.3 Profile-aware drift detection

`src/core/sop/detect-version.ts`:

- The canonical-snapshot signal source switched from `0.1.0/render.js` to `0.2.0/render.js`. A fresh project now reports `snapshot_in_sync` against the 0.2.0 canonical signals; any leftover 0.1.0 snapshot is reported as `snapshot_legacy` drift.

### 3.4 Gate / check / status / brief / advance

These callers were already profile-agnostic — they all read through `loadSopProfile()` — so the cutover is automatic:

- `check.ts`, `gate-runner.ts`, `status.ts`, `brief.ts`, `advance/advance-state.ts` now resolve required sections, artifact paths, and the next step from the 0.2.0 profile by default.
- `gate-runner.ts` still accepts an explicit `profile` override (introduced in PR 3); after the cutover, callers that don't pass one see 0.2.0.

## 5. MCP behavior

External schemas are unchanged:

- Tool names (`navigator.where_am_i`, `navigator.brief`, `navigator.run_gate`, `navigator.create_artifact`, `navigator.detect_sop_version`, `navigator.capture_log`, `navigator.generate_next_prompt`) — unchanged.
- Parameter shapes — unchanged.
- Response envelope shape — unchanged.

The only schema change is an **additive** widening of `navigator.create_artifact.artifactType` enum from the 5 0.1.0 ids to the full 19 0.2.0 ids. Adding values to a string enum is backwards-compatible for callers that already used the original 5.

Behavior naturally reflects 0.2.0 because the runtime default and project state are now 0.2.0:

- `navigator.where_am_i` returns `project.sopProfileVersion: "0.2.0"`.
- `navigator.brief` lists 0.2.0 required sections as blockers when the artifact is missing.
- `navigator.run_gate` validates 0.2.0 required sections.
- `navigator.create_artifact` can create any of the 19 0.2.0 artifacts.
- `navigator.detect_sop_version` reports `0.2.0 / 0.2.0` and `snapshot_in_sync` for a fresh project.

These are pinned by `tests/unit/mcp-sop-0.2-runtime.test.ts`.
