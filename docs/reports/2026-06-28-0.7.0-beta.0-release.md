# Release report — o-coding-navigation@0.7.0-beta.0

> Date: 2026-06-28 · Tag: `v0.7.0-beta.0` · Channel: npm `latest` + `beta`（`alpha` 保留在 `0.1.0-alpha.2`）
> SOP profile: `default-ai-coding-sop@0.5.0`（**不变** —— Contract Backbone 是引擎/CLI 特性，非 SOP bump）
> 版本号：npm 包 minor 升至 **0.7.0**，与 SOP profile 版本（仍 0.5.0）**继续解耦**。理由：契约主干新增第五类假完成检测（契约漂移），是与自动模式同级的能力跃迁，按软件能力集计为 minor 升级；SOP 工作流规范未变，故 profile 版本不动。

## What's in this release

**可选契约主干（Contract Backbone，AM-012 / DEC-037）** —— 第五类假完成检测：**契约漂移**。DESIGN 声明 API 契约，BUILD 写前端去调用它，过去没有任何环节校验两者一致。契约主干把声明契约当作唯一真相源，在 BUILD/VERIFY 机械交叉校验前端调用点——两边都不臆造。

- **声明即真相**：DESIGN 的 api-contract 产物可选携带 `ocn-api-contract` 标签栅栏（YAML）。栅栏标签是选择器，未打标签的 ```yaml/```json 块一律忽略，杜绝误把无关块当契约。
- **opt-in**：`.ocoding/config.yaml` 的 `contract.enabled`（默认 `false`）、`frontendRoot`、可选 `basePath`。未开启时一切字节不变。
- **DESIGN 块校验（exit 2）**：开启后若声明块缺失/无效/结构缺陷（重复 id、重复 method+path、非法方法、缺前导斜杠）→ `ERR_ARTIFACT_INVALID`。
- **BUILD/VERIFY 漂移门（exit 1）**：经 TypeScript 编译器 API 抽取 `.ts/.tsx` 调用点，与声明端点交叉校验；高置信度的未声明调用 / 方法不符阻断前进（`contract_drift`）。
- **三门同等 parity**：`ocn check` / `ocn gate` / `ocn advance` 都在 readiness 之后跑契约门（共享 `contract-gate-step` 编排）。
- **opt-in 模板**：`ocn doc create api-contract` 仅在开启时渲染 `ocn-api-contract` 脚手架块（空 endpoints，结构合法）。
- **brief 覆盖行**：开启时把 endpoints/calls/undeclared/method-mismatch/unverified 计数折进 `ocn brief`。
- **fail-safe，永不 false-closed**：前端根不存在 / TypeScript 不可用 → 跳过而非阻断；只读调用（MCP）报 `contract_unverified`（fail-closed，与 readiness 的 UNKNOWN-阻断对齐），不 fail-open 放行。
- **MCP 面零变化**：白名单恒 7 工具（测试钉死）。

同时纳入 **AM-011 / DEC-036（自动模式预触发独立专家评审）**：自动模式下任何 ai_agent 触发前先派一个全新上下文的资深专家评审子代理（建议性尽职调查，最多 3 次修复尝试；门禁仍是仲裁者）。引擎/CLI + 文本层特性，不 bump SOP 版本。

引擎/CLI 特性，沿 AM-008（Rewind & Cycle）/ AM-009（Auto Mode）先例不 bump SOP 版本。
