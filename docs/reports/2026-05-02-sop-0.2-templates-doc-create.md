## 1. Summary

This PR adds Markdown templates for every artifact id in the SOP 0.2.0
profile (00–18) and teaches `ocn doc create <id>` to recognise and emit the
nine new strong-gated build/verify artifacts (10–18). The runtime stays on
SOP 0.1.0 — `loadSopProfile()` still returns 0.1.0, `ocn init` still writes
0.1.0 snapshots, and the gate runner is unchanged. Templates simply become
available as inputs that PR 3 will wire into the runtime gate.

What this PR ships:

- Nine new strong-gated build/verify templates (`docs/10-build-plan.md` →
  `docs/18-final-build-verdict.md`), one TS file per template under
  `src/core/templates/`, each containing every required section heading the
  SOP 0.2.0 `data.ts` declares for that step.
- Five new design/plan-phase templates (`information-architecture`,
  `data-model`, `api-contract`, `test-strategy`, `mvp-plan`) for artifact
  ids 05–09, again containing the 0.2.0 required sections. These artifact
  ids exist in 0.1.0 too but with no required sections, so the existing
  0.1.0 gate ignores the additions.
- Additive backfills to the existing 00–04 templates (`project-brief`,
  `scope`, `prd`, `acceptance-criteria`, `technical-architecture`) so each
  template now satisfies both the 0.1.0 minimum and the 0.2.0 expanded
  required-section sets. No 0.1.0 heading was renamed or removed.
- Template registry expanded from 5 to 19 entries
  (`src/core/templates/index.ts`); `DOC_TYPES` and `isDocType` now list all
  19 ids in the same insertion order the test pins.
- CLI `doc create <type>` argument description switches from a hard-coded
  string to `DOC_TYPES.join(", ")` so help output stays in sync with the
  registry automatically.
- New tests: `tests/unit/sop-0.2-template-coverage.test.ts` (42 tests) and
  `tests/cli/doc-create-sop-0.2.test.ts` (13 tests).

What this PR does NOT change:

- Default runtime profile — `loadSopProfile()` still returns 0.1.0.
- `ocn init`, `ocn check`, `ocn advance`, `ocn brief`, `ocn status`, `ocn
  gate` behavior. None of them learned about 0.2.0.
- MCP tool surface. `navigator.create_artifact` keeps its hard-coded 5-type
  Zod enum and continues to reject the 9 new ids by design — MCP exposure
  for 0.2.0 templates is deferred to a later PR.
- SOP 0.2.0 `data.ts` required-section content. Templates were aligned to
  the existing wording, not the other way around.

## 4. Template coverage

`tests/unit/sop-0.2-template-coverage.test.ts` programmatically reads the
canonical SOP 0.2.0 `STEPS_BY_STATE` and `REQUIRED_SECTIONS_BY_STEP` and
asserts:

1. Every wired step (19 total) has a registered template in
   `src/core/templates/index.ts`.
2. Each template contains every required section that SOP 0.2.0 declares
   for its step, matched via the same `parseHeadings` + `matchSection`
   pipeline the gate runner uses. Aliases are the bilingual
   `English｜中文` and bare Chinese forms emitted by the `section()` helper
   in `0.2.0/data.ts`, so heading wording in the template matches the
   alias the matcher resolves.
3. The 9 new strong-gated build/verify templates pass the same coverage
   check as a focused subset (one zero-tolerance failure list per docType).
4. `writeArtifact` round-trips each new 10–18 template to its expected
   path.

All 42 assertions pass.

## 5. CLI `doc create` coverage

`tests/cli/doc-create-sop-0.2.test.ts` spawns the built CLI inside an
`ocn init`'d temp project and confirms, for each of the nine new ids:

- `ocn doc create <id>` exits 0.
- The output file lands at the correct `docs/NN-...md` path.
- Every required section heading from SOP 0.2.0 is present (using the same
  matcher the gate runner uses).
- The pre-existing overwrite semantics (block without `--overwrite`,
  succeed with it) hold for at least one new id (`verification-report`).
- An unknown id still fails with `ERR_ARTIFACT_INVALID` (exit 2).

`tests/cli/doc-create-expanded.test.ts` was extended (not replaced): its
locked `supportedTypes` array now lists all 19 ids in registry-insertion
order. The original five-type assertion lives below the comment "SOP 0.2.0
PR 2 (DEC-023) added templates for every artifact id 00-18 …".
