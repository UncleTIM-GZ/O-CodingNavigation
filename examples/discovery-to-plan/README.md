# Discovery to Plan Example｜从探索到计划

This example shows a minimal OCN project moving from **DISCOVERY** toward **PLAN** using only OCN's documented CLI surface and the bundled SOP profile.

> Validated with Claude Desktop on Windows with WSL2 (per [DEC-017](../../docs/20-decision-log.md) and [`docs/reports/2026-04-30-mcp-external-host-validation-report.md`](../../docs/reports/2026-04-30-mcp-external-host-validation-report.md)). Cursor and Cline are not yet verified.

## What this example demonstrates

- `ocn init` — bootstraps `.ocoding/` with a canonical SOP snapshot (`sop.yaml`, `gates.yaml`, `artifacts.yaml`, `config.yaml`) and a fresh `state.json` at `state_discovery / step_project_brief`.
- `ocn status` — reports the project's current state, step, and artifact path. Read-only.
- `ocn doc create <type>` — writes the bundled template for one of the five typed steps (`project-brief`, `scope`, `prd`, `acceptance-criteria`, `technical-architecture`) and emits `artifact_created` to the audit trail.
- `ocn check` — current-step generic since [P1-002](../../docs/reports/2026-04-30-check-current-step-generic.md). Resolves the artifact and required sections from `state.json` + the active SOP profile, never hard-codes `step_prd`.
- `ocn gate` — read-only gate aggregation against the current step. Same dispatch as `ocn check`, distinct exit code (`ERR_GATE_FAILED` vs `ERR_ARTIFACT_INVALID`).
- `ocn advance` — runs the gate, then advances to the next step on pass. Lock-protected; never partial. Emits a full audit chain with a shared `correlationId`.
- The current-step artifact validation surface (typed steps and artifact-only steps both flow through the same gate engine).
- The SOP snapshot files generated by `ocn init` (canonical, runtime-aligned per [P1-003](../../docs/reports/2026-04-30-sop-snapshot-runtime-sync.md)).

## Directory layout

```
examples/discovery-to-plan/
├── README.md                       # this file
├── docs/                           # 10 example artifact fixtures
│   ├── 00-project-brief.md         # state_discovery / step_project_brief — typed gate
│   ├── 01-scope.md                 # state_discovery / step_scope          — typed gate
│   ├── 02-prd.md                   # state_spec      / step_prd            — typed gate
│   ├── 03-acceptance-criteria.md   # state_spec      / step_acceptance_*   — typed gate
│   ├── 04-technical-architecture.md# state_design    / step_technical_*    — typed gate
│   ├── 05-information-architecture.md  # artifact-only (no required sections in v1.0)
│   ├── 06-data-model.md                # artifact-only
│   ├── 07-api-contract.md              # artifact-only
│   ├── 08-test-strategy.md             # artifact-only
│   └── 09-mvp-plan.md                  # artifact-only — last enumerated step in v1.0
├── .ocoding.example/               # explainer; DOES NOT contain real OCN state
│   └── README.md                   #   why .ocoding/ itself is intentionally absent
└── scripts/
    └── smoke.sh                    # end-to-end runner against a temp project
```

The five typed-gate fixtures are copied **verbatim from the bundled templates** (`src/core/templates/*.ts`) so they cannot drift from what `ocn doc create <type>` would produce in a fresh project at the same commit.

The five artifact-only fixtures are minimal but realistic — they document what each step's output is in this walkthrough, since v1.0 does not yet ship typed templates for them.

## Run the smoke

```bash
# from the repo root
npm run build                                       # only needed once per source change
bash examples/discovery-to-plan/scripts/smoke.sh
```

The script:

1. Allocates a hermetic temp project under `mktemp -d` (cleaned on exit; nothing under `examples/` or `~/.npm-global` is touched).
2. Runs `ocn init` in the temp project.
3. Copies this directory's `docs/` into the temp project's `docs/`.
4. Walks the SOP profile end-to-end: at each step it runs `ocn check`, `ocn gate`, then `ocn advance`. It stops when `advance` reports there is no further step (the v1.0 SOP profile defines steps from `step_project_brief` through `step_mvp_plan`; states past `state_plan` are stubs with empty step lists in `src/sops/default-ai-coding-sop/0.1.0/data.ts`).
5. Prints the final state / step.

### Expected result

The walk passes through **at least** the five typed steps:

- `step_project_brief`
- `step_scope`
- `step_prd`
- `step_acceptance_criteria`
- `step_technical_architecture`

And, because the bundled SOP profile defines five further artifact-only steps, the walk continues through:

- `step_information_architecture`
- `step_data_model`
- `step_api_contract`
- `step_test_strategy`
- `step_mvp_plan`

Final output ends with:

```
Discovery-to-plan smoke completed.
```

The exact terminal `currentStateId` / `currentStepId` printed by the final `ocn status` depends on how `advance` handles the transition past `step_mvp_plan` (the last enumerated step). The smoke does not assert a specific terminal step — it asserts that the walk does not crash, the per-step gates pass, and `advance` reaches a documented stop condition.

## Non-goals

- This is **not** a production project template.
- This does **not** validate Cursor or Cline (Claude Desktop only — see DEC-019 for the support boundary).
- This does **not** publish to npm.
- This does **not** promote `latest`.
- This does **not** authorise beta promotion.
- This does **not** invoke any MCP Host. The smoke exercises the CLI surface only; MCP Host validation is covered by [DEC-017](../../docs/20-decision-log.md) for Claude Desktop.
