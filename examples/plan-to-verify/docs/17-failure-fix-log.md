# Failure Fix Log｜失败修复日志

> Example artifact for **Mini Task Tracker CLI** (`mtt`).
> Required sections (SOP 0.2.0): Failed Item, Root Cause, Fix Applied,
> Re-test Result, Remaining Risk.
>
> The single entry below is **illustrative example evidence** of how a
> verification-time failure would be recorded. If a build observed no
> failures, the recommended pattern is to record an explicit "No failure
> observed" entry with the rationale (see the second entry below).

## Failed Item｜失败项

**Entry 1 — `done` integration test flake.**

`tests/integration/round-trip.test.ts: "done persists"` failed
intermittently — about 1 in 12 runs — during the v1.0.0 verification
window.

## Root Cause｜根因

**Entry 1.** The test created a task, then immediately referenced its id
to call `mtt done <id>`. The id was generated by ULID, but the test
captured it from `stdout` text instead of `--json`, and a parsing race
truncated the id when stdout flushed mid-line on the CI runner.

This was an input bug (test harness), not a logic bug (`mtt done` itself
worked correctly).

## Fix Applied｜修复方案

**Entry 1.** Switched the harness to spawn `mtt add --json` and read the
returned `data.task.id` from the parsed envelope. Removed the brittle
stdout regex. Tracked under (illustrative) PR #44.

## Re-test Result｜回归结果

**Entry 1.** `npm run test -- --repeat 50 round-trip` — 50/50 passes.
Documented in `docs/18-regression-evidence.md`.

---

**Entry 2 — No further failure observed.**

No additional verification failure was observed during v1.0.0. This
explicit entry replaces an empty section; SOP 0.2.0 requires the
section to exist, and a documented "no failure" record beats a silent
gap because it forces the team to confirm the absence rather than
assume it.

## Remaining Risk｜剩余风险

**Entry 1.** Other tests that still parse stdout text could exhibit the
same race; audit identified two candidates which were preemptively
converted to `--json` parsing in the same PR.

**Entry 2.** None observed; the absence-of-failure entry exists so a
future reviewer can confirm the section was reviewed, not skipped.
